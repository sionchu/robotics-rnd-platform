# Learning Roadmap

Statuses are evidence-based: `NOT STARTED`, `LEARNING`, `EXPERIMENTED`, `APPLIED`.
Bootstrap creation does not mark the user's learning as complete.

| Priority | Topic | Status | Evidence required to advance | Platform use |
|---|---|---|---|---|
| 1 | Linux and Git workflow | NOT STARTED | Reproduce branch, commit, recovery, process, permission, and service exercises | Safe daily engineering |
| 2 | Python engineering | NOT STARTED | Typed package, tests, profiling, packaging exercise | Core and experiments |
| 3 | Modern C++17 | NOT STARTED | CMake target, RAII/value semantics, tests, debugger exercise | Low-latency paths |
| 4 | Robotics math / transforms | NOT STARTED | Derive and test SE(3), frames, quaternion edge cases | All robotics work |
| 5 | OpenCV | NOT STARTED | Reproducible image pipeline and benchmark | Vision lab |
| 6 | Camera geometry / calibration | NOT STARTED | Calibrate, report reprojection error, retain generic fixture | Phase 1 |
| 7 | PnP / pose | NOT STARTED | AprilTag/ArUco pose experiment with uncertainty/failure cases | Guidance foundation |
| 8 | ROS 2 Jazzy | NOT STARTED | Nodes, topics/services/actions, launch, parameters, tests | Optional integration |
| 9 | TF2 | NOT STARTED | Publish/query a validated frame tree and compare to core math | ROS bridge |
| 10 | Robot interfaces and state | NOT STARTED | Extend mock contract and perform simulator/replay lab | RB control lab |
| 11 | 3D vision / point clouds | NOT STARTED | Acquisition-independent filtering/registration benchmark | Mech-Eye lab |
| 12 | PyTorch | NOT STARTED | CPU training/inference baseline with evaluation | AI experiments |
| 13 | CUDA / ONNX / TensorRT | NOT STARTED | Versioned GPU benchmark versus CPU baseline | GPU robotics |
| 14 | Isaac ROS | NOT STARTED | Supported hardware/software setup and one measured graph | Accelerated ROS |
| 15 | Simulation / Physical AI | NOT STARTED | Reproducible simulator scenario and sim-to-real assumptions | Digital twin/portfolio |

Each topic follows: theory -> runnable example -> exercise -> experiment -> project usage.
